# 感知、计数与结果

本文补充 `docs/架构与接口.md` 的实现建议，字段和状态名称尚不是已实现的 ROS 接口。先核对现有源码，再决定采用何种数据类或消息。

## 检测与 RGB-D 地图定位

- 先在实际仿真截图上验证候选类别，记录原图、模型/权重版本、阈值、推理耗时、正确检测和误检漏检。COCO 的 bottle 不表示特定饮料品牌。语音类别名需要映射到实际支持的类别。
- 将检测、深度几何和持久清单分成可检查的模块，先用现有轻量 Python 路线做最小验证。yolo_ros 可借鉴流程，不默认替换现有依赖或引入其整套管线。
- 同尺寸、同 frame_id、相同时间戳分别不能证明 RGB 与深度几何对齐。确认像素对应关系、CameraInfo 的成像模型、内参和是否矫正后，才能反投影。
- 深度单位依据实际编码和发布规范。当前已采样 `32FC1` 流按米解释，不套用 yolo_ros 示例中的默认 `/1000`；标准 `16UC1` 深度的毫米转换也需与实际流核对。保留原始编码和单位依据。
- RGB、深度、内参按采集时间对应；近似同步窗口需记录依据。处理框的缩放、裁剪、padding 时，把坐标映回相应原图。无效/过时输入标记无有效定位，不生成原点坐标凑数。

对于已确认适用的针孔模型和对齐深度，取目标有效区域的稳健深度 `Z`，使用对应像素 `(u,v)` 和内参：

```text
X = (u - cx) * Z / fx
Y = (v - cy) * Z / fy
p_map = T_map_camera(观测时间) * [X, Y, Z, 1]
```

避免直接取框中心的一个像素：中心可能落在背景或深度空洞。记录取样区域、有效样本比例与离散程度；遮挡明显时拒绝不可靠位置。为物品选取跨视角可比较的位置估计，说明表面点与物体中心的差别。至少三个位置的实测误差用于后续关联阈值选择。

## 持久关联与编号

视频 tracker ID 仅辅助短时关联。任务清单以 `task_id + object_id` 标识持久物品，保留类别、map 位置、首次/末次时间、有效观测次数与确认状态。

1. 仅让类别匹配、位于目标房间范围且定位有效的观测进入关联；拒绝过时帧和同一帧的重复处理。
2. 对同一批观测和已有物品做一对一分配；每条观测最多匹配一项，每项在同批最多更新一次。可用小规模贪心或最小代价分配，依近邻歧义的实测决定，不预设必须引入新库。
3. 空间距离门限由定位误差和最小物品间距共同决定。不能未经实验就把固定半径称为可靠去重；相近同类存在歧义时保留待确认状态。
4. 匹配成功更新位置和观测历史；未匹配观测先暂存，经过不同有效观测确认后分配/确认稳定编号。同一帧被重复读取不增加确认次数。
5. 短时离开视野不会删除已确认物品，重访时继续匹配旧记录。同一任务只统计已确认目标，跨任务是否复用清单需明确设计，默认不混算。

优先检查：单目标重访、同帧两个近邻、类别不同但位置相近、全无效深度、TF 缺失、重复时间戳、定位噪声和目标落在相邻房间。静态物品是首版假设；移动目标应单列能力和实验。

## 搜索状态与完成条件

可采用待命、导航、搜索、汇总、完成、失败、取消等状态；具体名称在实现时固定。每个观察点记录目标姿态、导航结果、观测时间段和有效传感器情况。

- 到达入口不代表已经完成房间搜索，识别首个物体后继续执行观察计划。
- 完成定义包含所有计划观察点成功执行、必要感知有效、结果保存成功。不可达点被跳过或关键数据缺失，应输出未完成/失败并保留部分清单。
- 完成且确认数量为零才是“已完成，找到 0 个”。未完成时可展示当前已确认数量，同时明确任务尚未完成。
- 本轮“通过”只对明确配置、场景、目标类别和观察计划有效；复杂遮挡下的漏检属于评估结果。

## 标注与保存

沿用架构草案字段：任务、配置版本、状态、清单、已完成/失败观察点、耗时和文件路径。可以先以 Python 结构化数据和 JSON 实现；不要因为草案里写了字段就声称接口存在。

保留原始地图图像/YAML，编号标记保存为独立图层或 RViz MarkerArray，并导出合成图。地图米坐标映射到像素需要处理 resolution、origin 平移与 yaw，以及图像行方向翻转；不要假定地图原点朝向为零。用已知点核对标注方向和边界。

保存后重新打开 JSON 和图片，核对 `count` 等于已确认记录数量、编号唯一、图上位置与清单一致。保留失败/取消任务的部分结果，避免把它们输出到“成功任务”目录中。

独立真值仅用于计算数量误差、重复/漏计、定位误差、执行耗时和失败率。结果计数不得读取仿真模型列表或真值坐标作为感知输入。
