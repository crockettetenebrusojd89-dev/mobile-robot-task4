# ROS 2 集成与排错

以下是本项目的 Humble 集成建议。来源和固定提交见 [GitHub 来源](github-sources.md)；具体操作以前述项目脚本和实际安装版本为准。

## 环境与消息

- 普通包操作使用 `source env.sh`；参与当前仿真的终端使用 `source sim_env.sh`。核对实际通信域、RMW、仿真 partition 和工作区覆盖顺序，不在其他实验终端全局改配置。
- 项目现有 `build.sh` 通过 `scripts/colcon_entry.py` 处理当前环境中的子进程等待问题。构建排错先读该入口和日志，再判断问题，避免改系统 colcon。
- 传感器输入先比对发布者/订阅者的 QoS，可用 `ros2 topic info <实际话题> -v`。传感器订阅参考项目已有的 sensor data QoS；可靠性只是兼容条件之一，还需检查 durability、类型和通信域。
- `ros2 topic list` 只证明能发现话题；实际消息、有效内容、频率、时间与 TF 是不同检查。采样使用限时和有限条数，不把探测进程留在后台。
- ROS 时间用于消息与 TF；仿真节点核对 `use_sim_time` 和实际 `/clock`。本地超时可使用单调时钟，不能拿它生成 ROS 观测时间。暂停/重置仿真后处理旧缓存和时间倒退。
- 回调保留源消息的 `header.stamp` / `frame_id`，避免以推理完成时间重打时间戳。耗时推理采用有界待处理队列，明确丢旧帧策略；不要让取消和状态回调一直等待推理。

## TF 与 SLAM

基础路径为 `odom → base_link → 传感器`；`map → odom` 在建图/定位阶段产生，M1 没有 map 不能直接判为基础 TF 失败。雷达 frame 使用真实消息中的完整名称。

核对每个 TF 的目标、源、单位、时间和发布者。坐标转换采用“把源 frame 中的点表达到目标 frame”，不靠交换 frame 名称纠正符号。区分相机固定安装、运动中的里程计和全局定位校正。

进入 SLAM 前检查有效 scan、观测时刻可用的 odom/底盘/雷达 TF，以及统一时间。房间图、物品图层和静态地图分别管理。

SLAM Toolbox 的栅格地图保存与 pose graph 序列化用途不同：供 AMCL/map_server 使用的图像/YAML 必须保存并重新加载；只有继续建图或 SLAM 定位确实需要时才另存图优化数据。不能把一种文件的存在当作另一种流程已验证。

## Nav2 Action 与房间观察点

使用与本机 Humble 对应的接口。可以借鉴 Nav2 Simple Commander，但调用前核实安装包版本和目标 Action 服务可用性。

1. 地图已加载、初始定位有效、相关 lifecycle 节点已激活，房间配置来自实际地图。
2. 发送目标后先判断是否被接受。Humble `goToPose()` 可返回 `False`；该情况不应继续按成功处理。
3. 等待执行结束后检查最终结果：`SUCCEEDED` 才算到达；`FAILED`、`CANCELED`、`UNKNOWN` 不能算到达。`isTaskComplete()` 为真只表示不再执行，失败或没有有效 future 也可能为真。
4. 给等待服务、激活、导航和取消设置应用层超时。Humble 的部分便捷方法会阻塞等待，不能从需要继续接收回调的路径无期限调用。
5. 取消请求后等待终态；超时保留失败/未完成信息和已观察物品，不向后续观察点继续派发目标。失败重试次数和代价有限，并保存原因。

当前路线拟用 NavFn A*。核对项目实际加载的配置显式设置 `use_astar: true`；已查阅的 Humble 上游示例是 `false`，仅使用 NavFn 这个插件不能证明运行了 A*。控制器和底盘参数沿用当前平台适配配置，不从别的机器人整份覆盖。

## 故障定位顺序

借鉴 Superpowers 的根因排查方法，按发生问题的边界收集证据：

| 现象 | 优先检查 |
| --- | --- |
| 有话题却收不到 | 类型、发布者是否活跃、通信域/RMW、QoS、当前 source 的工作区 |
| 有图像却无法定位 | 深度编码/有效值、对齐、内参、同步、观测时刻 TF |
| 导航不执行或结束异常 | lifecycle、Action 接受/终态、初始定位、目标 frame、可达性、costmap 与时间 |
| 重复计数或近邻合并 | 观测的 map 坐标质量、逐批一对一匹配、确认规则、阈值、room/task 范围 |

保留原始错误，尽量复现；找一条可工作的相同接口作对照；提出一个可测假设；改变最小相关因素并复查原症状。连续尝试没有新证据时，回到数据流和模块边界重新定位，不继续堆参数修改。
