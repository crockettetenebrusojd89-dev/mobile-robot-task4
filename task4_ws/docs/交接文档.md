## T2.2 三房间场景与评估真值

验证人 Codex。Gazebo 俯视图可见客厅、厨房、卧室及两个门洞。两个门洞的碰撞几何净宽均为 1.20 m。实时查询的椅子分布为 3 / 2 / 0，五把椅子的位置均与评估真值相同。保存 3 组 RGB-D 数据，机器人首帧中可见一把椅子。每组原始激光数据中，249 个连续回波与客厅西墙表面的位置相符。

当前三房间是项目自建的 `task4_home.sdf`。Codex 复核了教师教程链接，AWS 小屋仓库含配套 `map.pgm` 和 `map.yaml`，与教程二第 6 页截图吻合。该地图对应 AWS 小屋的布局。本机核对证据见 `results/m2_scene/2026-11-21_tutorial_map_review.YRziBQ/`。 [教程地图来源](../maps/README.md#教程里的地图来源)

本机证据保存在 `results/m2_scene/2026-11-21_t2_2.54gU3o/`，其中 `summary.json` 汇总各项检查，`overhead.png` 是 Gazebo 俯视图，`frames/frame_000.png` 是机器人相机图，`commands.txt` 记录仿真命令和退出码，`github_push.txt` 核对本次里程碑的提交与远端。椅子为自制简模，待 T3.1 检查检测器对仿真画面的识别效果。用户 GUI 复现和理解反馈待记录。 [启动与验证](../worlds/README.md#任务四三房间场景)

## T2.3 键盘建图

Codex 已在同一场景静止预跑 SLAM Toolbox，收到初始 `/map` 栅格（分辨率 0.05 m）及 `map → base_link` 变换，发现 `/undock` 和 `/cmd_vel`。起步时出现数条扫描队列满的日志，雷达注册后即收到地图。预跑证据保存在 `results/m2_map_nav/2026-11-21_t2_3_preflight.LXkCxR/`。实际驾驶、房间覆盖和用户 RViz 截图待 T2.3 验收。

用户已启动 Gazebo、SLAM 和 RViz。终端 D 从主目录执行时找不到 `sim_env.sh`，出坞请求停在等待服务端。Codex 从项目环境只读复查，ROS 域为 44，`/motion_control` 提供 `/undock`，`is_docked: true`。先在终端 D 按 Ctrl+C，再进入项目目录执行第 4 步。用户出坞结果待验证。本机证据见 `results/m2_map_nav/2026-11-21_t2_3_user_setup.jgzgzI/`。

地图对比时查到终端 A 的 Gazebo 在 ROS 域 44，终端 B 和 C 的 SLAM、RViz 在域 3。用户后续已恢复 RViz 显示，Codex 实测域 44 内 `/map` 由 SLAM 发布且有 RViz 订阅。终端仍需按下面步骤加载项目环境。 [地图对比](../maps/README.md#两套地图的实测对比)

四个终端均从 `task4_ws` 开始，依次执行。

1. 终端 A 启动 Gazebo，保持运行。

   ```bash
   TASK4_WORLD=task4_home bash start_sim.sh
   ```

2. 终端 B 启动 SLAM Toolbox，保持运行。

   ```bash
   source ./sim_env.sh && ros2 launch turtlebot4_navigation slam.launch.py use_sim_time:=true
   ```

3. 终端 C 打开 RViz。首张地图出现时检查 `Fixed Frame` 为 `map`，看左侧 `Map` 和 `LaserScan`。

   ```bash
   source ./sim_env.sh && ros2 launch turtlebot4_viz view_robot.launch.py use_sim_time:=true model:=lite
   ```

4. 终端 D 出坞，看到 `SUCCEEDED` 后再启动键盘控制。

   ```bash
   source ./sim_env.sh && ros2 action send_goal /undock irobot_create_msgs/action/Undock '{}'
   ```

   看到 `SUCCEEDED` 后运行。

   ```bash
   ros2 run teleop_twist_keyboard teleop_twist_keyboard --ros-args -p speed:=0.12 -p turn:=0.45
   ```

把焦点留在终端 D。`i` 前进，`j` 左转，`l` 右转，`k` 停车。先在客厅短距离试车，再逐个穿过门洞，让激光看清另外两间房的墙面。最后回到客厅起点附近，按 `k` 停车，保存一张能看出三间房与门洞的 RViz 截图。保留 A、B 两个终端供 T2.4 保存地图。 [T2.3 任务卡](任务四开发与验收路线.md#t23-键盘遥控建图用户键盘与-gui)

### 首次地图重影后的重建

用户已出坞并键盘驾驶一圈。截图显示墙线重影，键盘的速度上限升至 0.31 m/s、1.17 rad/s。Codex 保存了变形栅格和位姿图，并在当前位置另起 SLAM，生成了墙线清晰的局部预览。停稳后里程计朝向与 Gazebo 真值相差约 26°。对照出发点后，位置差约 1.9 m。日志提供的证据暂时无法判定突变是否由一次回环匹配触发。本机证据见 `results/m2_map_nav/2026-11-21_t2_3_distortion.EHBPpI/`。

保留 Gazebo 和 RViz。在终端 B 停止旧 SLAM，按第 2 步重新启动。机器人已经离座。在终端 D 停止旧键盘控制后，以 `speed:=0.10`、`turn:=0.35` 重新启动键盘节点。使用 `i`、`j`、`l`、`k`，其中 `q`、`w`、`e` 会分别调高速度上限。每次先走一小段或转一次，停车核对红色激光点能否贴在黑色墙线上。先扫客厅和一个门口再核对，墙线清楚后进入下一间房。出现突跳时停车，记录出事前后的地图与操作。

本次重开时，旧 SLAM 收到 Ctrl+C 后退出，随后 RViz 以 `-11`（段错误）退出。Codex 确认新 SLAM 已持续发布地图，在桌面终端重新打开 RViz，读到了 173 × 156 格起点栅格。用户可继续在新窗口核对激光。若以后仅 RViz 窗口消失，先核对终端 C 日志，Gazebo 和 SLAM 保持运行时可单独按第 3 步打开 RViz。日志和位姿图复核见 `results/m2_map_nav/2026-11-21_t2_3_rviz_recovery.YB7p6Q/`。

## T2.4 地图加载与定位

Codex 在新仿真重载 `task4_home_v1` 并验证了 AMCL。起步和结束的实测激光到障碍格距离中位数均约 2 厘米，Gazebo 实际移动 1.013 米，AMCL 估计移动 1.000 米。复现时先关闭旧 RViz、SLAM 和 Gazebo，再重新启动 `task4_home`。在单独终端进入 `task4_ws`，加载本项目环境后启动定位。

```bash
source ./sim_env.sh &&
ros2 launch turtlebot4_navigation localization.launch.py map:=maps/task4_home_v1.yaml use_sim_time:=true
```

定位终端保持在 `task4_ws`，相对地图路径可避开 Humble 启动配置对中文绝对路径的转义问题。本机如果一直等不到激光，可在仿真终端使用 `TASK4_USE_NVIDIA=0 TASK4_WORLD=task4_home bash start_sim.sh`。

AMCL 启动后，可在另一终端加载 `sim_env.sh` 并运行：

```bash
python3 scripts/set_initial_pose.py --x -0.4369 --y 1.7654 --yaw -0.4482
```

这组坐标对应刚启动时的默认生成点。若机器人已经移到别处，在 RViz 用 `2D Pose Estimate` 按实际位置和朝向给出初值。确认红色激光点贴到地图墙线上，再用低速试车检查位姿跟随。 [地图清单](../maps/manifest.json)

重载核对使用 194 × 159 个实测栅格，按原 PGM 的障碍、自由和未知分类逐格比较。修正 YAML 的自由区读取阈值后，14,767 个未知格继续保留。 [地图说明](../maps/README.md)

工程验证的原始证据在 `results/m2_map_nav/2026-11-22_t2_4_udp.775bcx0o/`，含激光叠图、AMCL 和 Gazebo 位姿、诊断命令，以及 GitHub 推送记录。隔离试验用 UDP 通信并临时移开了测试充电座。用户在原场景的 RViz 复现待记录。下一项按 T2.5 标定房间和观察点。

## 复现

在 `task4_ws` 的第一个终端执行 `bash start_sim.sh`。等 Gazebo 中出现机器人并运行后，在第二个终端执行：

```bash
source sim_env.sh
mkdir -p results/m1_sensor_check
run=$(mktemp -d results/m1_sensor_check/t1_1.XXXXXX)
python3 scripts/check_scan_clock.py --out "$run"
ros2 param get /robot_state_publisher use_sim_time
ros2 param get /diffdrive_controller use_sim_time
```

观察脚本输出以及目录中的 `scan_clock.json`、`clock_pairs.jsonl`。下次运行创建新目录，将新结果分别写入项目状态、工作记录与本页。
