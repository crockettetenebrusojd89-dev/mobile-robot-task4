## T1.1 实测摘要

| 运行 | `/scan` | `/clock` | 同窗有效配对 | 最大仿真时间差 | 一致 TF |
| --- | ---: | ---: | ---: | ---: | ---: |
| 首轮 | 226 | 974 | 190 | 0.138 秒 | 8 |
| 复测 | 210 | 936 | 182 | 0.123 秒 | 8 |

- 两次均为静止的 TB4 Lite maze 仿真。实际 scan frame 是 `turtlebot4/rplidar_link/rplidar`，参考 frame 是 `base_link`。
- 雷达原点在底盘系的平移为 `[0.00393584, 0, 0.13949272]` 米，约向前 3.94 毫米、向上 139.49 毫米。四元数 xyzw 为 `[0, 0, 0.707107, 0.707107]`，即绕 Z 轴旋转 +90°。与 TB4 Lite 安装模型和 `rplidar_stf` 一致。
- `/clock_bridge` 提供仿真时钟。复测中 `robot_state_publisher`、`diffdrive_controller`、`controller_manager` 和 `joint_state_publisher` 的 `use_sim_time` 均为 true。
- 本机原始记录在 `results/m1_sensor_check/2026-11-20_t1_1.wcd8p5/` 和 `results/m1_sensor_check/2026-11-20_t1_1_repeat.Xz5GZn/`，复测目录的 `summary.json` 汇总模型哈希、实测值和运行证据。原始日志保存在本机，Git 随项目维护本页摘要和可复现脚本。

## 复现

在 `task4_ws` 的第一个终端执行 `bash start_sim.sh`。等 Gazebo 中出现机器人并运行后，在第二个终端执行：

```bash
source sim_env.sh
mkdir -p results/m1_sensor_check
run=$(mktemp -d results/m1_sensor_check/t1_1.XXXXXX)
python3 scripts/check_scan_clock.py --out "$run"
ros2 param get /robot_state_publisher use_sim_time
ros2 param get /diffdrive_controller use_sim_time
```

观察脚本输出以及目录中的 `scan_clock.json`、`clock_pairs.jsonl`。下次运行创建新目录，将新结果分别写入项目状态、工作记录与本页。
