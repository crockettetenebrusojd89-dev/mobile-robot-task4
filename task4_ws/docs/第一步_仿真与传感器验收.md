# 第一步 启动仿真并确认传感器数据

今天的目标是跑起机器人，确认后续建图和视觉定位所需的数据。今天对应学习三个 ROS 概念：节点是运行的程序，话题是数据通道，消息是通道中传输的数据格式。

## 当前验证范围

本步骤使用现有 TurtleBot4 Lite/Fortress 和本地 maze 场景，作为开发验证平台。它尚不是最终的多房间任务场景，型号差异仍须结合教师要求核实。

start_sim.sh 和 sim_env.sh 已按本机启动文件编写，启动参数解析已检查通过。项目内 .compat 使用 Ogre2 传感器渲染配置和原始底盘控制参数，系统和其他实验目录保持原样。

2026-11-08 更新：用户截图已确认实际 GUI 与 RGB 画面，独立采样已收到 RGB、深度和 CameraInfo。完整数据频率、激光、里程计、clock、TF 及几何对齐仍待本步骤验收。相机学习操作见 [第一课](学习笔记/01_RGBD相机与ROS图像消息.md)。

## 终端 B 检查实际消息

```bash
cd '/home/hao/Documents/ChatGPT/自主移动机器人综合设计大项目/task4_ws'
source sim_env.sh
ros2 topic list -t
```

所有任务四终端使用相同 sim_env.sh。默认 ROS_DOMAIN_ID=44、IGN_PARTITION=task4_hao；仅在本机通信。

本机桥接配置包含下列话题，实际发布情况须逐项检查：

| 话题 | 含义 |
| --- | --- |
| /clock | 仿真时间 |
| /scan | 激光扫描 |
| /odom | 底盘里程计 |
| /oakd/rgb/preview/image_raw | 彩色图像 |
| /oakd/rgb/preview/depth | 深度图 |
| /oakd/rgb/preview/camera_info | 相机内参 |
| /tf 与 /tf_static | 坐标关系 |

使用下列命令逐项观察；每条持续输出的命令观察数秒后按 Ctrl+C，再执行下一条：

```bash
ros2 topic hz /scan
ros2 topic hz /oakd/rgb/preview/image_raw
ros2 topic hz /oakd/rgb/preview/depth
ros2 topic echo --once --qos-reliability best_effort /oakd/rgb/preview/camera_info
ros2 topic echo --once --qos-reliability best_effort /odom
ros2 topic echo --once /clock
```

话题名称出现只说明通道存在，不等于有数据。hz 应报告持续更新的频率；本步骤不预设必须达到的帧率。CameraInfo 中的图像尺寸和焦距应有效。

检查基础 TF：

```bash
ros2 run tf2_ros tf2_echo odom base_link
```

读取实际 CameraInfo 的 header.frame_id，再检查底盘到该坐标系的 TF。下列命令使用模型中的 optical frame 名称作为示例，若实际消息使用不同名称，应改用实际名称：

```bash
ros2 run tf2_ros tf2_echo base_link oakd_rgb_camera_optical_frame
```

此时尚未建图，没有 map 不算失败。后续需检查图像和深度的帧、尺寸、对齐关系及深度单位，不能仅凭名字认定对齐。

## 查看相机画面

终端 C 同样进入工作区并执行 source sim_env.sh，然后运行：

```bash
ros2 run rqt_image_view rqt_image_view
```

在话题下拉框选择 /oakd/rgb/preview/image_raw，确认有与仿真一致的画面。再查看深度话题，观察有效区域。深度显示可能需要可视化归一化；显示问题和数据缺失应分别排查。

## 通过标准和记录

- 仿真窗口正常，机器人成功生成。
- 彩色图像能实际显示，激光与图像/深度数据持续到达。
- CameraInfo 有效，odom 和 clock 有消息。
- odom 到底盘及底盘到实际相机 frame 的 TF 连通。
- 保存仿真画面、相机画面截图，以及命令输出和错误日志到 results/m1_sensor_check/。

如果图像话题有名字却没有数据，先检查仿真是否运行、相机桥接、渲染错误和终端仿真环境是否一致。根据具体日志修复，再进行本步骤验收。实际完成后更新 PROJECT_STATUS.md 和 WORKLOG.md。
