# 架构与接口草案

本文件是后续实现约定草案。只有 `task4_bringup` 的工作区信息入口已创建；以下业务模块和消息均尚未实现。

## 模块

语音解析 → 任务管理 → 房间导航与观察点搜索 → 感知识别与地图定位 → 物品清单与去重 → 汇总和地图标注。

- 任务管理维护待命、导航、搜索、汇总、完成、失败和取消等状态。
- 导航复用与已选平台兼容的 Nav2，感知复用固定版本的检测模型。
- 地图定位使用与 RGB 对齐的深度数据、对应相机参数，以及观测时刻的 TF。
- 清单在同一次任务中持久保留，短时视频跟踪 ID 只作为辅助信息。
- 仿真真值作为评估数据独立记录。

## 数据约定

| 数据 | 建议字段 |
| --- | --- |
| 任务 | task_id、room_name、object_class、开始时间 |
| 观测 | task_id、类别、置信度、观测时间、frame_id、地图三维位置、深度有效性 |
| 物品记录 | object_id、类别、位置估计、观测次数、首次与最后观测时间、确认状态 |
| 结果 | task_id、status、已确认目标数量、物品记录列表、耗时、已完成与失败观察点、文件路径 |

消息可以先在 Python 内部用结构化数据实现，再根据模块边界引入 ROS 自定义接口。当前未创建或锁定业务消息类型。

## 坐标与去重

地图坐标默认采用 `map`，单位为米；相机坐标以实际 optical frame 为准，不凭名称猜测朝向。相机话题、TF、图像尺寸和深度单位均须在 M1 实测后填写配置。

去重方案先验证静态目标的同类别空间关联。多个目标同时出现时须避免多条观测错误匹配到同一记录。暂存目标经过多次稳定观测后确认，阈值来源和误差要进入实验记录。

已完成搜索且未检测到目标，可以输出零。导航失败、未覆盖全部计划观察点或缺少关键传感器时，输出未完成或失败，并保留当前清单。

## 保存结果

每次实验创建独立目录，保存任务、配置版本、观察点执行情况、物品清单、耗时、带编号的地图图像和日志。原始占据栅格地图与物品标注分别保存，并导出合成图以满足展示要求。
