# 第二课补充：odom 到底是什么

日期：2026-11-09。接续第二课操作 B。本篇围绕用户实际截图解释坐标系与里程计，不新增运动操作。

## 从你的输出读出一句话

```yaml
header:
  frame_id: odom
child_frame_id: base_link
pose:
  pose:
    position:
      x: 约 -3.89e-12
      y: 约 -5.61e-24
      z: 0.0
```

header.frame_id 指明 pose 用哪套坐标系表达；child_frame_id 指明描述哪个坐标系。两项合起来的准确读法是：base_link 的原点在 odom 中的位置，以及 base_link 的坐标轴相对 odom 的朝向。机器人没有单一必然的几何中心；本项目用模型定义的 base_link 作为底盘参考。

你的回答“在 odom 坐标系中，描述底盘”正确。更精确地说，是底盘参考系原点的位置。消息中的极小数用科学计数法表示，e-12 是乘以 10 的负 12 次方；本次读数按数值精度可视为零。

截图的 orientation 约为 Quaternion(xyzw)=[0,0,0,1]，表示两套坐标轴几乎同向。w=1 是单位四元数的一部分，不能读成“转了 1 度”。

## 同名的三个概念

| 名称 | 它是什么 | 作用 |
| --- | --- | --- |
| 里程计 odometry | 根据运动观测连续估计位姿和速度的过程及结果 | 推算机器人移动了多少、转了多少 |
| /odom | 当前系统的 ROS 话题名，消息类型为 nav_msgs/msg/Odometry | 传递位置、朝向、速度及不确定性等数据 |
| odom | 当前里程计参考坐标系的名字 | 为位姿估计提供统一的原点和坐标轴 |

话题名与 frame 名是两个独立概念，可以取不同名字。`ros2 topic echo /odom` 读取消息，`tf2_echo odom base_link` 查询坐标变换。TF 表达和组合坐标关系，运动估计由相应的控制器或估计器产生。

## 用地板上的坐标纸理解 odom

设想机器人启动时，在地板上铺一张坐标纸：选定原点和 X、Y 正方向。在这一轮连续运行、没有重置参考系的条件下，odom 的原点与轴向保持固定；固定在机器人上的 base_link 则随机器人平移和转动。

```text
俯视图，教学假设：初始位置 (0,0)，初始朝向沿 odom +X

odom +Y
   ↑          终点 (1,1)，车头朝上
   |              ↑
   |              |
   |              |
   O ───────────→ (1,0) ───→ odom +X
 起点       先前进，再在此处左转 90°
```

| 理想运动阶段 | odom 中的位置 (x,y)，米 | 相对 odom 的朝向 |
| --- | --- | --- |
| 起点 | (0,0) | 0° |
| 沿初始前方前进 1 米 | (1,0) | 0° |
| 原地左转 90° | (1,0) | 90° |
| 再沿车头前进 1 米 | (1,1) | 90° |

转弯以后，底盘的 +X 方向朝向 odom 的 +Y，所以再次“向前”增加的是 odom 的 y。坐标纸保留原来的朝向。理想原地转动示例假定底盘参考原点位于转动中心；实际参考点有偏移时，其位置也可能变化。

常见实现会在初始化时把机器人附近设为 odom 原点，让初始估计接近零；具体原点和朝向由实现决定。截图表明当前估计接近原点，不能据此推定 odom 与 Gazebo 世界坐标或未来 map 坐标完全相同。重启仿真、重启里程计或显式重置可能重新初始化参考关系。

## 坐标数值从哪里来

odom 这套坐标轴提供参照；持续更新的位置数值由里程计算法估计。常见来源包括车轮运动反馈、视觉运动估计，以及与 IMU 等观测融合的估计器。

用差速底盘举例：左右轮这段时间分别走了多少，结合轮半径和轮距，可以推算底盘前进量与转角；不断把这些小段运动累加，得到当前位置和朝向。两轮等量前进对应直行，两轮行程不同对应转弯。这是在说明轮式里程计的基本原理，不意味着所有 /odom 都只用车轮。

本机静态配置中，irobot_create_control 的 diffdrive_controller 使用 left_wheel_joint/right_wheel_joint，open_loop=false，odom_frame_id=odom，base_frame_id=base_link，enable_odom_tf=true。这与轮运动反馈生成里程计、同时发布 TF 的配置一致。此处仅检查配置，没有查询当前 /odom 的运行时发布者，不能将配置检查写成运行时发布链路已核实。

## 为什么走一圈不一定准确回到零

里程计估计会受车轮打滑、尺寸参数偏差、观测误差等影响。假设实际前进 1 米，却估计成 1.02 米，多次累积后，估计位置与真实位置就可能越来越不一致，这叫漂移。

漂移主要说的是机器人相对实际环境的位姿估计误差增长。理解时继续把 odom 当成固定的局部参照，不能把它想成随着机器人移动的坐标轴。

odom 通常提供连续、平滑的短期运动估计。后续使用 SLAM 或地图定位时，会引入 map 作为全局任务参考，并用环境观测约束累积误差。map 中的估计也有误差，定位修正时还可能发生跳变。

```text
map → odom → base_link → 相机安装连杆 → camera optical frame
```

箭头表示 TF 树的父子关系。odom 到 base_link 表达局部运动估计；map 到 odom 表达定位模块计算的全局校正关系。相机到地图的点坐标换算通过组合这些关系完成。本项目最终要在地图标注物品，因此还需要 map 定位及时间对应，不能只看当前 /odom 就宣称有了可靠的物品地图坐标。

## 进一步区分：固定的 odom、map 与漂移

这里把“固定”说得更精确：在一轮没有重置的连续里程计运行中，odom 的原点和轴向不随机器人一起平移、转向，机器人相对 odom 的位姿估计连续变化。它是局部参考，不保证与真实房间永久、精确地对齐。前面的地板坐标纸用于解释轴向，并不保证这张“估计坐标纸”始终与实地标记准确重合。

map 也是坐标参考系，通常与全局地图关联。我们看到的栅格地图图像或地图文件则是描述环境的数据，二者应区分。常规定位过程中，map 提供全局参照，定位模块不断修正机器人在其中的估计。

| 比较项 | odom | map |
| --- | --- | --- |
| 主要目标 | 连续、平滑的局部运动估计 | 与地图环境一致的全局定位 |
| 常见估计来源 | 轮运动、IMU、视觉等相对运动观测及融合 | SLAM 或地图定位，将激光/视觉等观测与环境关联 |
| 估计连续性 | odom 到底盘的位姿应连续 | 定位修正后的机器人地图位姿可能跳变 |
| 长期误差 | 可能持续累积且没有界限 | 借助环境约束修正误差，仍非绝对准确 |
| 本项目用途 | 连续运动控制和局部运动参考 | 房间目标、物品坐标与地图标注 |

二者的核心差别在参考目的、误差约束与连续性，不能只用“固定还是移动”来区分。map 中的“跳变”通常指机器人估计位姿被校正，不表示机器人瞬移。

### 为什么固定坐标系中的估计仍会漂移

坐标原点选定以后，算法仍需测量每一小段运动并累加；测量与模型会有误差。以轮式里程计为例：

1. 车轮打滑：轮子转了相应圈数，底盘实际移动距离可能更短。
2. 参数偏差：用轮转角乘轮半径算行程，半径不准就会算错距离；轮距不准会影响转角估计。
3. 观测噪声、有限分辨率等误差：每次增量估计都可能有偏差。

如果持续多估或少估，小误差随运动积累；纯靠相对运动增量又缺少足够的外部参照，就难以知道自己已经算偏。所有里程计都必须考虑误差，但具体来源和变化程度取决于传感器、算法和环境。

教学例一：若每实际走 1 米都估成 1.02 米，同样的比例偏差下，实际走 10 米就会估成 10.2 米，差了 20 厘米。

教学例二：若朝向估计持续偏差 1°，再沿该错误朝向积分 10 米，就可能引入约 10×sin(1°)=0.175 米的横向误差。这个简化例子说明朝向误差也会转成位置误差，不是本机已测的漂移量。

“漂移”主要描述估计位姿与真实位姿的误差逐渐增长。小数 e-12 一类的数值残差，与行走后累积的显著定位漂移应分别理解。

### 两套坐标如何同时使用

```text
map → odom → base_link
```

箭头为 TF 父子关系，两段变换分别承担以下作用：

- map → odom：由全局定位/SLAM 提供校正。
- odom → base_link：由里程计提供局部连续运动估计。

取一个只沿 X 轴的一维教学例子：假设开始时 map 与 odom 原点、方向相同。之后机器人实际在地图 x=5.0 米处，里程计累积误差后估为 x_odom=5.3 米。此时地图定位也估计机器人在 x_map=5.0 米处，于是可得到 map 到 odom 的平移校正 -0.3 米：

```text
x_map = x_odom + t_map_odom
      = 5.3 + (-0.3)
      = 5.0 米
```

这里假设定位结果恰好等于真值，只用于展示坐标组合。现实定位仍有误差，旋转和三维情况还需完整变换组合。

里程计可以继续给出连续的 5.3 附近读数，全局定位把校正体现在 map → odom；因而从 map 查询到的机器人位置会更接近环境约束。不要为了修正地图位置直接把连续的 odom 位姿硬改到 5.0。

这也解释一个容易困惑的现象：从 map 看，估计的 odom 坐标系位置/朝向关系可以随定位校正而变化。“odom 不随车走”与“map 到 odom 的变换可更新”能够同时成立，因为前者强调局部参考和连续性，后者是在估计局部参考与全局地图之间的对齐关系。

在本项目中，要把相机看到的物品标到房间地图，后续必须结合观测时刻的 map、odom、base_link 与相机变换。当前用户截图仅验证了部分局部数据与 TF 接收，尚未测量本机漂移或运行 map 定位。
