# 第二课操作 C：激光雷达与 LaserScan

日期：2026-11-09。前置是能按说明运行仿真、source sim_env.sh，且已看到 /odom 和相机/底盘 TF 输出。用户已提交扫描元信息与接收频率，但明确表示尚不理解。本轮先解释这一步的目的与截图含义，理解后再用实际消息编写数据处理节点。

## 这一步与项目有什么关系

二维激光扫描给出同一平面内不同方向的距离回波。建图程序用这些回波观察墙体和障碍结构，再结合运动估计与 TF 累积环境信息；导航程序还可用回波更新局部障碍信息。单条 /scan 本身仍是雷达坐标系中的观测，不是已经定位好的全局地图，也不会直接给出杯子的类别和编号。

## 先读这段：这一步到底在干什么

本轮的实际任务，是确认后续建图程序将使用的激光消息能传到当前终端，并认识一条消息怎样描述周围环境。用户已经完成获取输出这项操作；这份截图能作为接收证据，知识理解仍需单独学习。

把一次二维扫描想成一张“沿四周不同方向测距的清单”。当前一条消息包含 640 个方向的距离样本，可以对应到同一水平扫描面内的回波。它们可能有多条打到同一面墙，也可能出现无有效回波的值；不能把 640 理解成有 640 个障碍物。

每个样本最关键的两个信息是：往哪个方向量（角度），该方向上的回波有多远（距离）。假设其中一个有效距离为 2.0，就表示对应方向测得的表面距离雷达约 2 米。这个 2.0 是教学例子，当前截图没有显示实际距离值。

```text
激光扫描：角度 + 距离 → 雷达周围的回波点
                      + 机器人运动与坐标变换
                      → 建图程序使用的环境信息
```

### 你的截图用日常语言怎么读

| 截图中的内容 | 实际意思 |
| --- | --- |
| ranges 的 length: 640 | 这条扫描消息中有 640 个距离样本；具体数值被隐藏了 |
| angle_min≈-3.14，angle_max≈3.14 | 扫描从约 -180° 到 +180°，覆盖一周，方向以本条消息的雷达参考系为准 |
| angle_increment≈0.00983 | 相邻两个样本方向间隔约 0.563°；这是角度间隔 |
| range_min≈0.164，range_max=12.0 | 声明的有效距离范围约为 16.4 厘米到 12 米；不是当前最近/最远障碍物的测量值 |
| average rate 约 57—58 | 当前工具每秒收到约 57—58 条扫描消息；一条消息中又有上述 640 个距离样本 |
| frame_id=turtlebot4/rplidar_link/rplidar | 这些角度和距离使用的雷达参考系名称，后续要检查其与底盘的 TF |

本次各行 average rate 可见值约 57.096—58.430 Hz，最后一行为 57.757 Hz。按最后一行计算，平均约每 17.3 毫秒收到一条消息。它不是电机转速，也不是“每秒只有 58 个测距点”；仿真可直接生成一组扫描，不能把接收频率等同于实物雷达机械转速。

`--no-arr` 的含义是隐藏数组，所以终端显示 ranges 的类型与长度，而不是列出 640 个值。intensities 是对应回波强度数据，本轮先不使用；从长度不能推定强度值有效或具有实物标定意义。

### 其余字段先知道它们属于哪一类

- header.stamp：本条消息中的扫描采集时间为 13.026 秒；属于消息时间，后续要与 /clock 一起检查。
- time_increment=0、scan_time=0：当前消息未提供可用的逐束时间间隔和扫描周期，不能用这两个零推断数据没有更新。连续接收情况已有 hz 输出作为另一项证据，具体时序仍待检查。
- hz 下方的 min、max：接收间隔的最小/最大值，截图约 0.009—0.029 秒，单位是时间，区别于上方以米为单位的 range_min/range_max。
- std dev：接收间隔的波动程度；window：用于这次统计的间隔样本数。它们用于后续排查，不要求当前一次掌握全部统计方法。

## 重点看这些字段

| 字段 | 含义与单位 |
| --- | --- |
| header.frame_id | 本条扫描所属的雷达参考坐标系，以实际输出为准 |
| header.stamp | 本次扫描第一束回波的采集时间；本轮先记录，后续结合 /clock 验收 |
| angle_min、angle_max | 扫描起始/结束角，单位弧度 |
| angle_increment | 相邻两束回波的角度间隔，单位弧度 |
| range_min、range_max | 距离有效量程边界，单位米 |
| ranges | 每束对应的距离，单位米；本轮因 --no-arr 被隐藏 |

π 弧度等于 180°，π/2 等于 90°。零角方向沿本消息 frame 的 +X；正角按绕 +Z 的右手方向计算，Z 朝上时从上方看是逆时针。

不要先把数组第 0 项或零角方向当作机器人正前方。当前模型的静态 URDF 中雷达相对底盘有约 +90° 偏航安装，实际消息 frame 和安装 TF 仍须查询确认，先记录真实 frame 名。

## 下一轮开始实现的数据算法

第一段程序将分为两层：ROS 订阅回调负责收消息；纯数据函数负责筛选并计算。这样可以单独理解并验证每一层。

对数组中从 0 开始编号的第 i 束：

```text
θ_i = angle_min + i × angle_increment
r_i = ranges[i]
x_i = r_i × cos(θ_i)
y_i = r_i × sin(θ_i)
```

得到的是雷达坐标系中的二维回波点。先排除 NaN、正负无穷和超出有效量程的数值，再进行距离统计和最近有效回波计算。NaN/Inf 等无效读数不能直接当作障碍物坐标；最近回波也不一定是机器人前方的障碍，更不直接等于可安全通行距离。

教学例子：某束角度为 0 弧度、距离为 2 米，则雷达平面坐标为 (2,0) 米。若角度为 π/2、距离为 2 米，则约为 (0,2) 米。这里不代表当前场景已采到这些数值。把点换到底盘或地图还要用实际 TF。

节点初版只输出摘要，不发布运动命令。后续再结合安装 TF 计算底盘方向上的扇区距离，并在独立验证后用于导航或控制。
